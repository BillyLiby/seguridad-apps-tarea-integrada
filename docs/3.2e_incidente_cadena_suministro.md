# 3.2e Incidente de cadena de suministro: Ultralytics en PyPI (diciembre de 2024)

## Qué ocurrió
En diciembre de 2024 se publicaron en PyPI versiones maliciosas de `ultralytics` (8.3.41, 8.3.42, 8.3.45 y 8.3.46), una biblioteca de visión por computador muy utilizada. PyPI las retiró. Según el análisis de PyPI, **no se explotó ninguna falla de PyPI**: el atacante comprometió primero los flujos de GitHub Actions del proyecto.

## Mecanismo de compromiso
1. El atacante abusó de los workflows de GitHub Actions del repositorio. El propio análisis de PyPI indica que se apuntó a la caché de Actions usada durante la fase de build.
2. Las primeras versiones maliciosas salieron por el workflow legítimo (que usaba *Trusted Publishing*), por lo que el paquete publicado parecía auténtico.
3. En una segunda tanda se usó un token de API de PyPI que seguía vigente en el entorno del workflow, posiblemente anterior a la adopción de Trusted Publishing. Estas versiones no tenían actividad de repositorio ni atestaciones de publicación correspondientes, lo que permitió distinguirlas.

Lección central: el eslabón débil fue el **proceso de build/publicación (CI/CD)**, no el código fuente revisado.

## Relación con este proyecto
Este laboratorio usa GitHub Actions (3.5) y dependencias de PyPI (FastAPI, PyJWT, etc.), así que se expone al mismo tipo de riesgo.

## Dos controles aplicables al proceso de desarrollo usado
1. **Fijar dependencias con hashes y fijar las Actions por SHA de commit.** `pip install --require-hashes -r requirements.txt` rechaza cualquier artefacto distinto del revisado; en el workflow, `uses: actions/checkout@<sha-completo>` en vez de una etiqueta móvil. Verificación: el pipeline falla si una dependencia o acción no está fijada.
2. **Endurecer el workflow:** permisos mínimos (`permissions: contents: read`), sin `pull_request_target` con código no confiable, sin compartir cachés entre contextos de distinta confianza, sin tokens de larga duración (usar Trusted Publishing si algún día se publica) y auditoría del workflow con `zizmor`. Verificación: `zizmor .github/workflows` sin hallazgos altos.
